# 冷链温控与批次放行台

冷库与冷藏车的温控值班台：录冷库与探头、登批次、盯温度记录、算超限与断链、判放行还是拒收。

## 运行

```
npm install
npm start
```

默认端口 5244（`PORT` 可以覆盖），数据存在 `data/db.json`，页面在 `/`。

## 页面

- **概览**：冷库与运行中数量、探头数量与已过校准期的探头数、批次总数与各状态条数、温度记录条数与人工记录数、放行与拒收条数、当前满足放行条件的批次数与被挡下的批次数、没有任何温度记录的批次数、归属存疑记录条数与重叠窗个数、最高与平均 MKT、按冷库一行给出探头与批次数。
- **冷库与探头**：冷库台账（编码、名称、类型、位置、库位、状态）与探头台账（编号、所属冷库、位置、状态、校准有效期、记录条数），都带增改删。
- **批次**：批次清单（批次号、品名、规格、件数、所在冷库、入库时刻、状态、温度记录条数、存疑条数、最长超限、累计超限、MKT、断链数、放行情况），行内展开逐条温度记录、超限段、断链缺口、**设备占用与归属（占用段历史、重叠窗与切割结果、存疑与错位记录、从别批裁入的记录）**、放行判定五项与放行单，并提供「放行」「拒收」「修改批次」入口。
- **设备占用账**：当前重叠裁决口径说明（可跳设置改）、按探头画的占用时间轴（一种颜色一个批次，斜纹段是重叠窗，悬停看切开后各计几条）、占用账行（批次/设备/探头/起止/时长/来源/重叠状态，带登记、修改、拆分、删除）、重叠窗与切割结果表（先后顺序、各得子时段与记录数、存疑数）。
- **温度记录**：记录清单（批次、探头、时刻、温度、来源、登记人、是否超限、**归属状态与判定归属批次**），支持按批次、探头、来源、归属状态与时刻筛选、单条新增与删除。
- **放行台账**：放行与拒收记录（批次、决定、时刻、经办人、当时的 MKT、最长超限、累计超限、断链数与依据）。

## 归属与隔离（记录落在「批次 + 设备 + 探头 + 时段」上）

温度记录不再因为"谁先录"就算谁的，而是对照**设备占用账**判归属：

1. **设备占用账 `occupancies`**：记录哪个批次在什么时段占着哪个冷库/车厢的哪台探头。行分两种：设备行（只占设备，未指定探头）与探头行（精确到探头）。新建批次自动开一条设备行；按既有温度记录回填探头行；批次放行/拒收按决定时刻收口；批次换库位/换车厢**必须填交接时刻**，旧占用段保留、新段从交接时刻起开口——早先的记录永远挂在对得上设备的老时段上。占用账可以手工增改删，也可以把一条占用在某时刻**拆分**并把后半段交给另一个批次。
2. **每条记录一个归属状态**：`明确`（该时段探头/设备唯一占用方就是标签批次）、`重叠裁得`（多个批次重叠占用，按口径裁给标签批次）、`账外归他`（按口径裁给了别的批次，批次详情里可一键"改挂"）、`存疑`（没有占用账覆盖、同设备多批共用又没登记探头归属、**同一探头同一时刻挂了不同批次的两条读数**、或口径判不了——不计入任何批次）。存疑记录的消解手段按原因区分：没账的补占用账、交接不清的拆分占用或改挂、同刻两条读数的删掉录错的那条。
3. **重叠裁决口径**（都在设置里改，页面同步写明）：
   - `overlapPolicy` 重叠怎么切：`midpoint` 中点切分（默认，重叠窗按先后均分成 n 段，各算各的）/ `firstWins` 先占者全得 / `suspend` 整段挂起（窗内全部存疑）；
   - `boundaryPolicy` 边界时刻算谁的：`leftClosed` 左闭右开（默认，切点/交接时刻归先占用批次）/ `rightClosed` 左开右闭（归后占用批次）；
   - `overlapTieBasis` 裁决依据（谁先谁后）：`occupyStart` 占用开始时刻（默认）/ `loadedAt` 批次入库时刻 / `recordFirst` 该探头最早记录时刻。
4. **放行判定第五条**：没有归属待定（存疑）或错位的温度记录。存疑或错位存在时不能放行，必须补占用账、拆分交接或改挂记录消疑。前四条（单次/累计超限、断链、探头校准）维持不变。
5. 设备级兜底：某设备在该时段只有一个批次占着、即使没登记到具体探头行，该设备探头的记录也归这一批；同一设备多批共用且都没登记探头归属时，记录判存疑而不是随便归一边。

## 口径（页面上的说明与数字都要与本段一致）

1. **温度带**：默认 2 到 8 摄氏度（可在设置里改），低于下限或高于上限都算超限。
2. **超限段**：按时刻顺序逐条判，连续超限的时段算一段，**中间只要有记录回到范围内就断开**；每段的时长按该段相邻记录的实际时刻差累加。
3. **累计超限**：一个批次从入库到当前，所有超限段的时长之和；**跨月不重置**，按批次周期累计。
4. **断链**：相邻两条记录的时刻差超过 `chainGapMinutes`（默认 15 分钟）算一处断链，缺口时长按实际时刻差算。
5. **MKT（平均动力学温度）**：按动力学公式算，写成 `MKT = −Ea / (R × ln((Σ e^(−Ea/(R·T)) ) / n)) − 273.15`（活化能 Ea 取 83144 J/mol、气体常数 R 取 8.314，T 用开尔文，n 为参与计算的记录条数）；**不是把温度取平均**。
6. **放行判定五条**：单次连续超限不超过 `allowExcursionMinutes`（默认 30 分钟）、累计超限不超过 `allowTotalExcursionMinutes`（默认 120 分钟）、全程没有断链、**参与判定的探头都在校准有效期内**、**没有归属待定（存疑）或错位的温度记录**。五条同时满足才算满足放行条件；**没有任何温度记录的批次不能放行**。
7. **同一探头同一时刻既有自动记录又有手工更正记录时，以手工记录为准**；停用探头名下的记录不参与判定。
8. **停用与检修中的冷库**：其批次仍然照常记录与判定，但在清单里要标出来。

## 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | /api/health、/api/summary、/api/settings | 健康检查、概览、设置（PATCH 可改） |
| GET / POST | /api/rooms | 冷库清单（支持 status、type、keyword）/ 新增 |
| GET / PATCH / DELETE | /api/rooms/:id | 详情（含探头与批次）/ 修改 / 删除 |
| GET / POST | /api/probes | 探头清单（支持 roomId、status）/ 新增 |
| PATCH / DELETE | /api/probes/:id | 修改 / 删除 |
| GET / POST | /api/batches | 批次清单（支持 roomId、status、product）/ 新增 |
| GET / PATCH / DELETE | /api/batches/:id | 详情（含记录、超限段、断链、占用账、归属明细、放行单）/ 修改（换设备必须带 `movedAt`）/ 删除 |
| GET | /api/batches/:id/release-check | 这个批次的放行判定（含归属第 5 条） |
| GET | /api/batches/:id/attribution | 批次视角的归属明细（占用段、重叠窗、存疑/错位/裁入记录） |
| POST | /api/batches/:id/decision | 放行或者拒收，body `{decision, decider, decidedAt, basis, remark}` |
| GET / POST | /api/occupancies | 设备占用账（支持 roomId、probeId、batchId）/ 手工登记 |
| GET | /api/occupancies/timeline | 按探头的占用时间轴与重叠窗（支持 probeId、roomId、from、to） |
| PATCH / DELETE | /api/occupancies/:id | 修改占用行 / 删除 |
| POST | /api/occupancies/:id/split | 在 `at` 时刻拆分占用，可带 `toBatchId` 把后半段交给另一批次 |
| GET / POST | /api/records | 温度记录（支持 batchId、probeId、source、attribution、from、to）/ 新增 |
| PATCH / DELETE | /api/records/:id | 改挂记录（只允许改 batchId、remark）/ 删除一条记录 |
| GET | /api/releases | 放行台账（支持 batchId、decision） |

出错的返回统一是 `{"error":{"code":"...","message":"...","details":{...}}}`，`details` 里会点名是哪个字段没过。
