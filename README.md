# 冷链温控与批次放行台

冷库与冷藏车的温控值班台：录冷库与探头、登批次、盯温度记录、算超限与断链、判放行还是拒收。

## 运行

```
npm install
npm start
```

默认端口 5244（`PORT` 可以覆盖），数据存在 `data/db.json`，页面在 `/`。

## 页面

- **概览**：冷库与运行中数量、探头数量与已过校准期的探头数、批次总数与各状态条数、温度记录条数与人工记录数、放行与拒收条数、当前满足放行条件的批次数与被挡下的批次数、没有任何温度记录的批次数、归属有问题的批次数、最高与平均 MKT、按冷库一行给出探头与批次数。
- **冷库与探头**：冷库台账（编码、名称、类型、位置、库位、状态）与探头台账（编号、所属冷库、位置、状态、校准有效期、记录条数），都带增改删。
- **批次**：批次清单（批次号、品名、规格、件数、所在冷库、入库时刻、状态、温度记录条数、最长超限、累计超限、MKT、断链数、放行情况），行内展开设备占用段、逐条温度记录（含归属）、归属有问题记录（可改判/剔除/撤销）、超限段、断链缺口、放行判定六项与放行单，并提供「放行」「拒收」入口。
- **设备占用账**：占用窗台账（批次、设备、探头、起止时刻、用途、进行中/已结束、计入记录数、存疑记录数，带增改删与一键结束）；下方按探头给出时间线切片账——占用窗按开始时刻排先后、标出与谁重叠，时间片分独占（绿）/交叠（红）/空档，逐片给出记录数、计入数、存疑数；页头写明当前交叠与边界口径。
- **温度记录**：记录清单（批次、探头、时刻、温度、来源、登记人、是否超限、归属状态），支持按批次、探头、来源、归属状态、时刻区间筛选，归属有问题的记录可直接改判计入、人工剔除或撤销改判。
- **放行台账**：放行与拒收记录（批次、决定、时刻、经办人、当时的 MKT、最长超限、累计超限、断链数、归属问题数与依据）。

## 口径（页面上的说明与数字都要与本段一致）

1. **温度带**：默认 2 到 8 摄氏度（可在设置里改），低于下限或高于上限都算超限。
2. **超限段**：按时刻顺序逐条判，连续超限的时段算一段，**中间只要有记录回到范围内就断开**；每段的时长按该段相邻记录的实际时刻差累加。
3. **累计超限**：一个批次从入库到当前，所有超限段的时长之和；**跨月不重置**，按批次周期累计。
4. **断链**：相邻两条记录的时刻差超过 `chainGapMinutes`（默认 15 分钟）算一处断链，缺口时长按实际时刻差算。
5. **MKT（平均动力学温度）**：按动力学公式算，写成 `MKT = −Ea / (R × ln((Σ e^(−Ea/(R·T)) ) / n)) − 273.15`（活化能 Ea 取 83144 J/mol、气体常数 R 取 8.314，T 用开尔文，n 为参与计算的记录条数）；**不是把温度取平均**。
6. **放行判定六条**：至少有 1 条参与判定的温度记录（没有记录的批次不能放行）、单次连续超限不超过 `allowExcursionMinutes`（默认 30 分钟）、累计超限不超过 `allowTotalExcursionMinutes`（默认 120 分钟）、全程没有断链、**参与判定的探头都在校准有效期内**、**没有归属存疑/设备对不上/占用窗外/挂错批次/人工剔除的记录**。全部满足才算满足放行条件。
7. **同一探头同一时刻既有自动记录又有手工更正记录时，以手工记录为准**；停用探头名下的记录不参与判定。
8. **停用与检修中的冷库**：其批次仍然照常记录与判定，但在清单里要标出来。
9. **设备占用账（归属与隔离）**：每条温度记录必须落到「批次 + 设备 + 探头 + 时段」上。占用窗 `occupancies` 登记某批次在哪段时间占用哪个冷库/车厢上的哪台探头（结束时刻留空表示进行中；一个批次可登记多段，对应多趟运输或搬库位；探头允许为空，表示占了设备但没有探头）。同一探头的占用窗允许交叠——交叠不是录入错误，账上如实显示。
10. **交叠裁决 `overlapPolicy`（设置里可改）**：`window`（默认，按占用窗逐点切）——记录时刻只落进一条占用窗就归该批；同时落进多条窗的交叠内核拆不开，一律标「交叠存疑」，**不计入任何一边的判定**，两边批次都被第 6 条挡住，需人工改判或删除。`first`（先占先得）——交叠时刻判给开始更早的占用窗，挂在另一批名下的读数标「挂错批次」并计入占用方。`manual`——交叠点一律先存疑，等值班员逐条裁定。
11. **边界时刻 `boundaryPolicy`（设置里可改）**：两条占用首尾相接（如 05:00–12:00 与 12:00–20:00），`front`（默认）按 [起, 止] 计，12:00:00 这一点算随车走完的前一批；`back` 按 [起, 止) 计，算接手的后一批。被切点的记录标「边界切分」。
12. **归属状态八种**：归属明确、边界切分（以上两种计入判定）、交叠存疑、占用窗外（该时刻这台探头没有任何占用）、设备对不上（探头台账所属设备与占用账不一致，常见于批次改库位/车厢或探头被挪）、挂错批次（占用方明确是别的批次）、人工计入、人工剔除（后五种不计入）。人工改判优先级最高；改判与撤销都留痕（旧改判标记为被替代）。
13. **改库位/挪探头不回写历史占用账**：批次或探头改了所属设备后，历史时段的占用窗保持原样，对不上的时段在判定里标「设备对不上」；确认账记错了可直接修改对应占用窗。

## 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | /api/health、/api/summary、/api/settings | 健康检查、概览、设置（PATCH 可改） |
| GET / POST | /api/rooms | 冷库清单（支持 status、type、keyword）/ 新增 |
| GET / PATCH / DELETE | /api/rooms/:id | 详情（含探头与批次）/ 修改 / 删除 |
| GET / POST | /api/probes | 探头清单（支持 roomId、status）/ 新增 |
| PATCH / DELETE | /api/probes/:id | 修改 / 删除 |
| GET / POST | /api/batches | 批次清单（支持 roomId、status、product）/ 新增 |
| GET / PATCH / DELETE | /api/batches/:id | 详情（含记录、超限段、断链、放行单）/ 修改 / 删除 |
| GET | /api/batches/:id/release-check | 这个批次的放行判定 |
| POST | /api/batches/:id/decision | 放行或者拒收，body `{decision, decider, decidedAt, basis, remark}` |
| GET / POST | /api/records | 温度记录（支持 batchId、probeId、source、status、onlyProblems、from、to）/ 新增 |
| DELETE | /api/records/:id | 删除一条记录（连带删掉它的改判单） |
| GET / POST | /api/occupancies | 设备占用窗（支持 batchId、roomId、probeId、active）/ 新增 |
| GET | /api/occupancies/timeline | 时间线切片账（支持 roomId、probeId；按探头分 lane，含独占/交叠片、计入与存疑计数、当前口径说明） |
| PATCH / DELETE | /api/occupancies/:id | 修改 / 删除（删窗后记录重算为占用窗外；指向该窗的生效改判随窗软撤销） |
| GET / POST | /api/attribution-overrides | 归属改判台账（支持 recordId、active）/ 新增，body `{recordId, kind: assign|exclude, occupancyId, reason, operator}`；同一记录重复提交会把旧改判标为被替代 |
| DELETE | /api/attribution-overrides/:id | 撤销改判（记录回到自动裁决），body `{operator, reason}` |
| GET | /api/releases | 放行台账（支持 batchId、decision） |

出错的返回统一是 `{"error":{"code":"...","message":"...","details":{...}}}`，`details` 里会点名是哪个字段没过。
